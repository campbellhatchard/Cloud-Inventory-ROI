## Supporting findings

- `process.id` exists on many saved records but new governed rows use positional `P-###` generation and catalog lookup still relies on a composite display key.
- `gap.id` is persisted, but the associated application is not.
- `src/shared/handoff-readiness.js` reads all selected rows, including inactive/historical rows, and accepts a typed Solution Engineer name.
- server output routes load only handoff JSON, so they cannot currently derive the authoritative Primary SE display name.
- `public/solution-fit-output-builders.js`, `src/exports/operational-pdf.js`, `src/exports/solution-fit-turnover-docx.js`, and Christie context filter only `selected`; they do not share an active-scope contract.
- no PostgreSQL schema change is required for application/gap IDs because handoff state is already persisted as JSONB and `primary_se_id` is already a governed column.
